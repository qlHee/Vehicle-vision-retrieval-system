# 车辆视觉检索系统（Vehicle Visual Retrieval System）

基于局部特征的车辆图像检索系统。通过提取车辆图像的 SIFT / ORB 局部特征，使用 BoF / VLAD 编码生成图像表示，结合 TF-IDF 加权与 KNN 近邻检索实现"以图搜图"。系统在初始检索基础上进一步提供**重排序**（线性组合 / 图传播）与**查询扩展**（自动 QE / 用户辅助 QE）两类后处理手段，并配套图形界面与命令行评估两种使用方式。

适用场景：车辆追踪与重识别、交通违章车辆查询、停车场车位管理、保险理赔车辆核查等。

---

## 功能特性

- **两种特征提取**：SIFT（128 维，鲁棒性好）、ORB（32 维，速度快）
- **两种特征编码**：BoF（词袋直方图）、VLAD（累积残差，细节更丰富）
- **TF-IDF 加权**：降低常见视觉词权重，提升区分性
- **KNN 检索**：余弦相似度度量，返回 Top-10 相似车辆
- **重排序（Reranking）**
  - 线性组合重排序：原始得分(0.7) + 颜色(0.15) + 纹理(0.08) + 形状(0.07)
  - 图传播重排序：基于 Manifold Ranking 的相似度图信息传播
- **查询扩展（Query Expansion）**
  - 自动 QE：对 Top-k 结果做 Average QE 二次检索（k 可在 1–10 间调节）
  - 用户辅助 QE：在界面中手动勾选正确结果参与扩展，逼近检索性能上界
- **图形界面**：交互式检索、算法切换、Top-10 结果展示（绿框正确 / 红框错误）、PR 曲线、特征编码直方图
- **性能评估**：8 种算法组合（SIFT/ORB × BoF/VLAD × 有无 IDF）的 Precision@K、Recall@K、mAP@K 批量评估

## 目录结构

```
.
├── main.py               # 主入口：GUI 模式 / 评估模式
├── gui_app.py            # 图形界面与数据库加载、缓存逻辑
├── feature_extractor.py  # 特征提取（SIFT/ORB）与编码（BoF/VLAD/TF-IDF）
├── image_retrieval.py    # KNN 检索器、性能评估器、数据库加载
├── reranking.py          # 线性组合重排序 + 图传播重排序
├── query_expansion.py    # 查询扩展（自动 QE / 用户辅助 QE）
├── requirements.txt      # 依赖列表
├── run.sh                # 启动脚本（激活 venv 并启动 GUI）
└── data/
    ├── image/            # 数据库图像，按车牌号分子文件夹存放（946 张 / 51 类）
    ├── test/             # 测试集图像，按车牌号分子文件夹存放（42 张 / 14 类）
    └── .cache/           # 运行后自动生成的缓存目录（见下文）
```

数据组织约定：`image/` 与 `test/` 下每个子文件夹以**车牌号**命名，同一文件夹内为同一辆车的多张图像。检索时以"相同车牌号"作为正样本判定标准。

## 快速开始

### 启动图形界面

```bash
python main.py --mode gui
```

或使用启动脚本（会自动激活 `venv` 并启动 GUI）：

```bash
./run.sh
```

界面操作流程：

1. 点击 **Select Image** 选择一张查询图像
2. 在控制面板选择特征算法（SIFT/ORB）、编码方法（BoF/VLAD）、是否启用 TF-IDF
3. 点击 **Search** 执行检索，右侧展示 Top-10 结果（绿框=正确匹配，红框=错误匹配）与 PR 曲线
4. 可选：点击 **Rerank (Liner)** / **Rerank (Graph)** 对结果重排序
5. 可选：设置 `top` 值后点击 **Query Expansion** 做查询扩展；或先勾选若干正确结果再扩展（用户辅助 QE）
6. 点击 **Histogram** 查看特征编码直方图，点击 **Evaluate** 在测试集上批量评估

### 命令行评估模式

对 4 种编码组合（BoF、BoF+IDF、VLAD、VLAD+IDF）批量评估，并生成图表与报告：

```bash
python main.py --mode eval                       # 结果输出到 ./results
python main.py --mode eval --output ./my_results # 指定输出目录
```

可选指定数据路径：`--image_folder <路径>` 与 `--test_folder <路径>`（默认使用 `data/image` 与 `data/test`）。

输出包括：`comparison.png`（精度/召回/时间对比）、`pr_curves.png`（PR 曲线）、`map_comparison.png`（mAP@K 曲线）、`report.txt`（文本报告）。

## 关于首次运行与缓存

**首次运行会比较慢。** 启动 GUI 后，系统需要在后台完成一次性的预处理：

1. 读取 `data/image/` 下全部图像（946 张）并提取每张图的 SIFT 与 ORB 特征
2. 分别为 SIFT、ORB 用 K-means 构建视觉词典（K=256）并计算 IDF 权重
3. 并行预计算 8 种编码组合（SIFT/ORB × BoF/VLAD × 有无 IDF）的检索索引

这一过程根据机器性能可能需要数十秒到数分钟。界面底部状态栏会显示进度（如 `Extracting: 200/946`、`Building codebook...`、`Building indexes...`），请耐心等待至加载完成。

**预处理完成后，系统会把结果写入缓存目录 `data/.cache/`（缓存文件 `database_cache.pkl`）。** 之后再次启动时，系统会优先读取该缓存，跳过特征提取与索引构建，**几乎瞬间完成加载，无需再次等待**。

缓存说明：

- 缓存以**相对路径**存储图像位置，因此即使把整个项目复制或移动到其他目录，缓存依然有效、可直接复用，无需重新预处理。
- 缓存通过对数据库内容计算哈希来校验。当 `data/image/` 内的图像发生增删改导致哈希变化时，缓存会自动失效并触发一次重新预处理（即再次经历一次较慢的首次运行）。
- 如需强制重新生成缓存，删除 `data/.cache/` 目录即可：

  ```bash
  rm -rf data/.cache
  ```

## 算法概览

系统采用**离线 - 在线两阶段架构**：

- **离线阶段（数据库构建）**：加载图像 → 提取局部特征 → K-means 构建码本 → BoF/VLAD 编码 → 计算 IDF（可选）→ 构建 KNN 索引。该阶段的结果即被缓存到 `data/.cache/`。
- **在线阶段（查询检索）**：提取查询图像特征 → 同方法编码 → KNN 检索 Top-K → （可选）重排序 →（可选）查询扩展 → 展示结果。

各模块关键点：

- **BoF**：将描述子硬分配到最近视觉词，统计词频直方图，L2 归一化。
- **VLAD**：累积描述子与最近聚类中心的残差，幂次归一化 + L2 归一化，保留更多细节。
- **TF-IDF**：`idf(w) = log((N+1)/(df(w)+1)) + 1`，出现越少的视觉词权重越高。
- **线性组合重排序**：`Score = 0.7·S_orig + 0.15·S_color + 0.08·S_texture + 0.07·S_shape`。
- **图传播重排序**：相似度→高斯核亲和度→对称归一化→Manifold Ranking 迭代 `f^(t+1)=α·W·f^(t)+(1-α)·y`→与原始得分融合。
- **Average QE**：`q_exp = normalize((q + f₁ + … + f_k)/(k+1))`，k 越小越稳健（噪声样本越少）。

## 实验结论摘要

基于测试集（42 张查询 / 946 张数据库）的评估，核心结论：

- **编码方法**：VLAD 显著优于 BoF；ORB+VLAD（P@1≈90.5%，检索 ~8.9ms）是速度与精度的最佳平衡。
- **TF-IDF**：对 BoF 有一定提升，对 VLAD 影响有限（VLAD 本身已保留足够区分性信息）。
- **查询扩展**：自动 QE 对 k 值敏感，初始精度有限时建议 k=1~2（k=1 时 mAP@10 +3.60pp）；k≥5 反而引入噪声、损害性能。
- **用户辅助 QE（Oracle 上界）**：用户勾选正确结果后 mAP@10 可从 28.37% 提升至 44.21%（+15.84pp），P@1 提升约 31pp，验证了人机交互勾选设计的高价值。
- **重排序**：图传播重排序对 mAP@5/mAP@10 普遍有提升（K 越大越明显）；线性组合重排序整体提升有限。两者效果均与原始检索质量强相关。

详细数据与分析见仓库内文档。

## 改进方向

- 根据p@10自动调节图重排的权重，p@10越高，图重排权重越高
- 根据查询图像和结果图像智能调节线性组合重排序的权重，例如查询图像和结果图像涉及白天黑夜晴天雨天等不同场景，加大光照不敏感的算子权重
- 引入深度学习特征（如 CNN 特征）进一步提升检索效果
- 采用更高效的索引结构（KD-Tree、LSH）加速大规模检索
- 结合车辆属性（颜色、车型）进行多模态检索
- 针对数据集对重排序参数（α、β、σ）与 QE 默认 k 值进行调优
